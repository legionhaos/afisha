# Telegram-бот афиши

Бот работает через aiogram 3 и long polling, только в личных сообщениях. Все карточки и справочники получаются из backend; встроенного каталога нет.

## Запуск

Нужен Python 3.12+. Запустите backend и из каталога `bot` выполните:

```bash
python -m venv .venv
# Windows PowerShell
.venv\Scripts\Activate.ps1
# Linux/macOS: source .venv/bin/activate
pip install -e ".[test]"
```

Создайте в `bot` файл `.env` (не публикуйте токен):

```dotenv
BOT_TOKEN=токен_от_BotFather
API_BASE_URL=http://localhost:8000/api/v1
API_TIMEOUT=20
```

Запуск: `python -m app.main`. Тесты: `python -m pytest`. `API_BASE_URL` должен включать префикс `/api/v1`. Для контейнера можно собрать образ из каталога `bot`: `docker build -t afisha-bot .` и запустить с `--env-file`, указав URL backend, доступный из контейнера. Существующий compose не запускает бота. Не запускайте одновременно несколько экземпляров polling с одним токеном.

## Возможности и ограничения

`/catalog` — выбор города, категории, даты и цены, страницы и подробная карточка; `/subscribe` — подписка по городу, категории и периоду; `/subscriptions` — список; `/unsubscribe` — удаление всех подписок с подтверждением; `/cancel` — сброс текущего сценария и диалога; `/start`, `/help` — справка. Обычный текст отправляется в `/chat`; подтверждение действий агента отключено, поскольку backend сейчас отклоняет `confirm_action_id`. Для подписки используйте `/subscribe`. Для подписок используется отдельный API и передаётся Telegram chat ID. Отмена или повторное использование кнопки не отправляет мутацию.

Запросы разных пользователей обрабатываются параллельно, а действия одного пользователя в одном чате сериализуются средствами FSM. Состояние, блокировки и незавершённые подтверждения находятся в памяти процесса и теряются при перезапуске; несколько экземпляров бота не разделяют эту изоляцию. После POST выполняется GET и сверяются ID и параметры активной подписки; после DELETE проверяется отсутствие активных подписок. При ошибке проверки результат считается неизвестным. GET показывает текущее состояние и не доказывает, что запрос изменил его, если совпадающая подписка уже существовала. Показываются первые 90 городов и категорий из справочника; поиск по всем городам доступен даже при пустом списке городов. Даты вычисляются backend в UTC+5: «выходные» — ближайшие суббота и воскресенье (в воскресенье — следующие), «неделя» включает сегодня и следующие семь дней. Ограничение цены применяется к минимальной цене билета, поэтому другие билеты могут быть дороже. Нулевые цены без признака бесплатного входа отображаются как неуказанные. Нет фоновой отправки уведомлений: backend предоставляет хранение подписок, а не реализованный в боте планировщик рассылки. Подтверждение подписки через чат агента отключено: backend не предоставляет достаточно данных для проверки её параметров и не передаёт Telegram chat ID. Используйте `/subscribe`. Backend сейчас отклоняет подтверждения агента и не аутентифицирует API подписок; подтверждение в боте не устраняет ограничения безопасности backend. Не выставляйте backend в недоверенную сеть без защиты. Возможности чата и наличие реальных событий зависят от backend и его данных.
